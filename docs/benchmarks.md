# Benchmarks, data and queries

_Generated by `scripts/make_docs.py` from `src/bencholap/benchmarks/`._

All benchmarks run on **Apache Iceberg tables** (Parquet files, format version 2) through an
Iceberg REST catalog and S3-compatible storage, and the only engine plugin today is **Trino**
(Iceberg connector). Other table formats or connectors (Hive, Delta Lake, ...) and other engines
need a plugin; see "Adding an engine" in the README.

Results are derived from TPC-H / TPC-DS / ClickBench and are not comparable to published results.

## TPC-H (derived)

TPC-H models a wholesale supplier: 8 tables (lineitem and orders are the large ones) and 22
ad-hoc decision-support queries with joins, aggregations and subqueries. Data comes from
`tpcgen-cli` (byte-identical to the official `dbgen`). SF1 is about 1 GB of raw data (6 million
lineitem rows); queries use the specification's validation parameters (`qgen -d`), so SF1 results
are checked against the official answer set.

- Tables: `region`, `nation`, `supplier`, `customer`, `part`, `partsupp`, `orders`, `lineitem`
- Scale factors: 1, 10, 30, 100, 300, 1000
- Definition: [`src/bencholap/benchmarks/tpch/benchmark.yaml`](../src/bencholap/benchmarks/tpch/benchmark.yaml)

## TPC-DS (derived)

## ClickBench (derived)

ClickBench (by ClickHouse) is one wide table of anonymized web-analytics events (`hits`,
105 columns) and 43 queries typical of dashboards and ad-hoc analysis: scans, COUNT DISTINCT,
high-cardinality GROUP BY, string search, top-N and date-range reports. Data is ClickBench's own
Parquet dataset (100 files of about 1 million rows); SF N loads the first N files, so only SF100 is
the full ClickBench dataset. The queries and the load (raw table plus timestamp conversion) are
ClickBench's own Trino versions. ClickBench publishes no answers, so results are compared between
configurations only.

- Tables: `hits`
- Scale factors: 1, 10, 100
- Definition: [`src/bencholap/benchmarks/clickbench/benchmark.yaml`](../src/bencholap/benchmarks/clickbench/benchmark.yaml)

### Table layouts

| layout | published setup | what it is |
|---|---|---|
| `unpartitioned` (default) | yes: [ClickBench presto-iceberg (create.sql, insert.sql, load)](https://github.com/ClickHouse/ClickBench/tree/main/presto-iceberg) | One unpartitioned Iceberg table written with a single INSERT and default settings, as in ClickBench's presto-iceberg setup (no ANALYZE after loading). |
| `small-row-groups` | no | Unpartitioned and unsorted like the published setup, but written with Parquet row groups of at most 100,000 rows. The control for the sorted and bloom-filters layouts, which use the same row group size, so their effect can be separated from the effect of smaller row groups. _bencholap control layout for pruning tests, not a published ClickBench setup._ |
| `sorted` | no | Rows sorted by ClickBench's primary key (CounterID, EventDate, UserID, EventTime, WatchID) when written, so min/max statistics let scans skip row groups for the many queries that filter on CounterID = 62 and an EventDate range. Trino sorts each written file (ranges can overlap between files) and the row groups have at most 100,000 rows, so there are row groups to skip. _The sort order is the primary key of ClickBench's reference ClickHouse table; applying it to an Iceberg table is a bencholap layout for pruning tests, not a published ClickBench setup._ |
| `date-partitioned` | no | Identity partitioning by EventDate (one partition per day, 31 days in July 2013). Date-range queries (Q36-Q42) can skip whole partitions during planning. _bencholap layout for partition-pruning tests, not a published ClickBench setup._ |
| `bloom-filters` | no | Unpartitioned and unsorted, with Parquet bloom filters on UserID, URLHash and RefererHash: the point lookups of Q19 (UserID = ...) and Q40/Q41 (RefererHash / URLHash = ...) can skip row groups whose min/max range contains the value but whose bloom filter does not. Row groups have at most 100,000 rows; a row group that contains the looked-up value is still read. _bencholap layout for bloom-filter tests, not a published ClickBench setup._ |
